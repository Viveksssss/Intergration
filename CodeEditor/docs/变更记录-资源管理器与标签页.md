## 二、架构变化

### 改动前

```
QMainWindow
 └── setCentralWidget(CodeEditor)      ← 整个中间区只有一份编辑器
```

问题：整个程序只有**一个** `QTextDocument`，天然无法开多个文件。

### 改动后

```
QMainWindow
 ├── QToolBar   [打开文件夹][资源管理器] | [打开文件][保存] | [跳转行] | [折叠][展开] | [换行]
 ├── QSplitter (Horizontal, handle=1px)
 │    ├── FileExplorer        左侧资源管理器（默认隐藏，打开文件夹后出现）
 │    └── EditorTabs          右侧标签页
 │          ├── Tab0: BlankPage（欢迎页，不可关闭）
 │          ├── Tab1: CodeEditor  ← 独立 document / 高亮 / 折叠
 │          └── Tab2: CodeEditor
 └── QStatusBar  行/列 ... 行数/字符数
```

**关键设计：每个标签页 = 一个全新的 `CodeEditor` 实例。**
因为 `CodeEditor` 构造时自己 `new CodeHighlighter(document())`、`_folds.setDocument(document())`，
所以多个实例天然互不干扰，**原类一行代码都不用改**。

## 三、新增文件详解

### 3.1 `fileexplorer.h`

纯声明，暴露 3 个接口 + 2 个信号：

```cpp
bool    openFolder(const QString &dirPath);   // 切换根目录
void    setFilterVisible(bool on);            // 过滤框（默认隐藏）
void    setHeaderText(const QString &text);   // 标题栏文字

signals:
    void fileActivated(const QString &filePath);   // 点了文件
    void openFolderRequested();                    // 点了标题栏 ⤢
```

**为什么它不负责读文件？**
读文件属于「外壳的职责」，资源管理器只负责「告诉外面用户点了什么」。
这样 `FileExplorer` 可以脱离编辑器单独复用（比如以后做图片预览器）。

成员：

| 成员 | 作用 |
|---|---|
| `QFileSystemModel *_model` | Qt 自带文件系统模型，**自带后台线程**，异步加载目录 |
| `QTreeView *_tree` | 树视图，只显示第 0 列（文件名） |
| `QLabel *_title` | 标题显示当前文件夹名 |
| `QToolButton *_pickBtn` | `⤢` 按钮，触发 `openFolderRequested` |
| `QLineEdit *_filter` | 名称过滤框，默认 `hide()` |
| `QString _rootPath` | 当前根目录绝对路径 |

### 3.2 `fileexplorer.cpp` 关键实现

**(1) 模型配置**

```cpp
_model->setFilter(QDir::AllDirs | QDir::Files | QDir::NoDotAndDotDot | QDir::Drives);
_model->setReadOnly(true);
_model->setNameFilterDisables(false);
```

`NoDotAndDotDot` 去掉 `.` 和 `..`，`Drives` 让磁盘根也能列出来，
`setNameFilterDisables(false)` 让被过滤项**直接消失**而不是变灰（变灰会让树看起来像坏了）。

**(2) 隐藏多余列**

```cpp
for (int c = 1; c < _model->columnCount(); ++c)
    _tree->hideColumn(c);
```

`QFileSystemModel` 默认 4 列（名称/大小/类型/修改时间），全显示会把树撑得很宽。

**(3) 展开根节点的坑 —— 异步信号**

```cpp
QObject::connect(_model, &QFileSystemModel::directoryLoaded,
                 this, [this](const QString &path) {
    if (_rootPath.isEmpty()) return;
    if (QDir(path) == QDir(_rootPath))
        _tree->setExpanded(_model->index(path), true);
});
```

`QFileSystemModel` 是在**自己的线程**里读目录的，`setRootPath()` 返回时子项还没读出来，
此时 `expand()` 是空操作（因为还没有子节点可展开）。
必须在 `directoryLoaded(path)` 信号里再展开一次，这是最容易被漏掉的一步。

**(4) 单击 vs 双击**

```cpp
_tree->setExpandsOnDoubleClick(false);   // 双击 = 打开文件，展开交给箭头
```

`onTreeClicked`：目录 → 走默认展开逻辑；文件 → `emit fileActivated(绝对路径)`
`onTreeDoubleClicked`：目录 → 手动切展开状态；文件 → 同样 `emit`

> 代码审阅提示：`onTreeClicked` 里对文件的 `emit` 与 `onTreeDoubleClicked` 会**同时**触发（
> 双击必然先产生一次 `clicked`）。因为 `MainWindow::onFileActivated` 走的是
> `EditorTabs::openFile()`，内部有「已打开则直接切换」的去重判断，所以重复调用是幂等的，不会开出两个标签。

**(5) 为什么不用 `QSortFilterProxyModel` 做过滤**

代理层会让 `QFileSystemModel` 的懒加载失效——为了判断「某个子节点是否匹配」，
代理会递归请求所有子节点，等于把整棵磁盘树扫一遍。
本实现改用 `setNameFilters()`（模型自带的名称过滤，作用在已加载节点上），
代价是**只过滤已经展开过的层级**，对本地小工程足够。

### 3.3 `editortabs.h` 核心接口

```cpp
CodeEditor *openFile(const QString &filePath);        // 打开（已开则切过去）
CodeEditor *openContent(const QString &title, const QString &text,
                        const QString &filePath = {}); // 用内容新建
CodeEditor *currentEditor() const;
QString     currentFilePath() const;
bool        isDirty(int index) const;
bool        saveIndex(int index, const QString &path = {});
bool        maybeClose(int index);                    // 脏文件弹窗确认
```

### 3.4 `editortabs.cpp` 四个关键点

#### ① 用 `setProperty()` 挂元数据，而不是改 `CodeEditor`

```cpp
editor->setProperty("filePath",   absPath);   // 文件绝对路径
editor->setProperty("savedText",  text);      // 上次保存时的全文
```

`QObject::setProperty()` 是 Qt 的通用「动态属性」机制，不用给 `CodeEditor` 加成员变量，
也就**完全不用碰原类**。读到用 `property("filePath").toString()`。

#### ② 脏标记 = 文本比对，不用 `document()->setModified()`

```cpp
bool EditorTabs::isDirty(int index) const {
    CodeEditor *e = editorAt(index);
    if (!e) return false;
    return e->toPlainText() != e->property("savedText").toString();
}
```

**为什么不用 `modified()`？**
`CodeEditor` 内部（`mainwindow.cpp` 原 `openFile`、`codeeditor.cpp` 的 `QPlainTextEdit` 基类）
会自己调用 `setModified(false)`，外部再依赖这个标志容易打架。
改成「和上次保存的内容字符串比较」后，只要 `savedText` 更新时机正确，脏标记就永远准。
标签标题显示为 `文件名 ●`。

#### ③ 打开内容用 `beginEditBlock` 包起来

```cpp
QTextCursor c(editor->document());
c.beginEditBlock();
c.insertText(text);
c.endEditBlock();
c.movePosition(QTextCursor::Start);
editor->setTextCursor(c);
```

如果直接 `insertPlainText(text)`，每插入一行都会触发一次 `contentsChange`，
`CodeEditor::onTextChanged` → `FoldManager::rescan()` 会被调用 N 次，打开大文件明显卡顿。
`beginEditBlock/endEditBlock` 把整批修改合并成**一次**文档操作。

#### ④ 空态占位页

```cpp
_blank = new BlankPage(this);          // 私有命名空间里的 QWidget 子类
addTab(_blank, "欢迎");
bar->setTabButton(0, QTabBar::RightSide, nullptr);   // 摘掉关闭按钮
```

好处：程序启动时 `currentWidget()` 永远非空，`MainWindow` 拿到的 `_editor` 是个安全值（`nullptr`），
空态下点状态栏/折叠按钮也不会崩，只是统一走 `resetEditorState()`。

### 3.5 关闭流程（`maybeClose`）

```
isDirty?
 ├── 否 → removeTab + deleteLater
 └── 是 → QMessageBox(Save | Discard | Cancel)
      ├── Cancel  → return false（不关）
      ├── Discard → removeTab
      └── Save    → 有路径 → saveIndex()
                   无路径 → getSaveFileName() 另存为后再 saveIndex()
```

#### ⚠️ 关闭按钮为什么一开始「点了没反应」（重要实战教训）

第一版用 `setTabsClosable(true)` 依赖 Qt 自带的 close-button，结果用户反馈「标签关不掉」。
诊断过程（写了临时程序渲染按钮像素，验证完即删）：

| 检查项 | 结果 |
|---|---|
| `tabBar()->tabButton(i, RightSide)` | 存在，`CloseButton`，16×16，`visible=1` |
| 点击信号 `tabCloseRequested` | 正常发出 |
| **按钮像素** | **几乎全透明 —— 图形根本没画出来** |

**根因**：`theme.cpp` 里写了

```css
QTabWidget#editorTabs QTabBar::close-button { image:none; border-radius:2px; margin:2px; }
```

`image:none` 把唯一的图形抹掉了；而 Fusion 风格下描边色约 `#2c2c36`，
标签底色是 `#1a1a21` —— 两者几乎同色，等于一个**看得见位置、看不见图标、还能点**的空洞。
用户自然会认为「这个标签没法关闭」。

**修复**：弃用自带按钮，改为自绘 `CloseButton`（`QToolButton` 子类）：

```cpp
void paintEvent(QPaintEvent *) override {
    QPainter p(this);
    if (underMouse()) {                       // 悬停蓝底
        p.setBrush(Theme::kSelectionBg);
        p.drawRoundedRect(rect().adjusted(0,0,-1,-1), 3, 3);
    }
    p.setPen(QPen(hot ? Qt::white : QColor(0x9a,0x9a,0xac), 1.4, Qt::SolidLine, Qt::RoundCap));
    p.drawLine(4, 4, w-5, h-5);               // 两根 45° 线 = ×
    p.drawLine(w-5, 4, 4, h-5);
}
```

要点：
1. **不受 QSS 影响**：自绘不经过 `::close-button` 伪元素，主题怎么写都不会再弄没图标。
2. **下标会变**：增删 / 拖动标签后按钮 index 失效，所以每次结构变化都调
   `renumberCloseButtons()` 整体重挂（`setTabButton` 会接管旧按钮所有权并销毁它）。
3. **`setFocusPolicy(Qt::NoFocus)`**：否则点完 × 焦点留在按钮上，继续敲字没反应。
4. **点击转发**：按钮里 `emit bar->tabCloseRequested(_tabIndex)`，复用同一条关闭流程。

#### ⚠️ 顺带修的真实 bug：`maybeClose` 里 `e` 已失效

```cpp
CodeEditor *e = editorAt(index);
...
removeTab(index);   // ← 此时 widget 已从 tab 里摘掉
e->deleteLater();   // ← 这里 e 还有效，但再往后就是悬空指针
```

原版在 `removeTab` 之后还读了 `tabText(index)`，此时该下标已经指向**别的标签**（或越界）。
现在这些取值全部提前到 `removeTab` 之前完成，`removeTab` 之后只做「定位新当前页」。

#### 关闭入口一共给了 5 条路径

| 入口 | 触发方式 |
|---|---|
| 标签上的 × | 单击（自绘按钮） |
| 标签右键菜单 | 关闭 / 关闭其他 / 关闭右侧标签 / 关闭所有 |
| 工具栏「关闭标签」 | 按钮或 `Ctrl+W` |
| 工具栏「全部关闭」 | 按钮或 `Ctrl+Shift+W` |
| 中键点击标签 | 需自行加 `QTabBar::mouseReleaseEvent`，本版未做 |

快捷键用 `WindowShortcut` 作用域挂在 `QMainWindow` 上（`buildShortcuts()`），
这样焦点在编辑器内部时也能触发，且不会和 `QPlainTextEdit` 自带的按键处理互相抢。

#### 批量关闭的下标安全

```cpp
bool EditorTabs::closeOthers(int keepIndex) {
    for (int i = count() - 1; i >= 0; --i) {   // 从后往前
        if (i == keepIndex) continue;
        if (!maybeClose(i)) return false;
    }
}
```

**必须倒序遍历**：删掉第 i 个会让 i 之后的所有下标前移，正序遍历会跳过元素。

### 3.6 `fileops` —— 文件操作（右键菜单的后端）

全部做成**静态函数**，不依赖任何 Widget 状态（只收一个 `parent` 用来定位对话框），
好处是可以脱离界面单独测试、也能直接挂到菜单栏。

```cpp
QString uniquePath(dir, baseName);                 // 新建文件.txt / 新建文件 2.txt
QString newFile(parent, dir);                      // 新建空文件
QString newFolder(parent, dir);                    // 新建文件夹
QString rename(parent, oldPath, newName, &error);  // 改名
bool    removeToTrash(parent, paths);              // 删除（回收站优先）
void    showProperties(parent, path);              // 属性对话框
void    revealInExplorer(parent, path);            // 在资源管理器中定位
bool    isValidName(name, &why);                   // 合法性校验
int     baseNameLength(fileName);                  // 重命名时选中哪一段
```

#### ① 安全红线：删除只走回收站

```cpp
if (QFile::moveToTrash(p))
    continue;
// 失败才记录，让用户二次确认「永久删除」
needPermanent << p;
```

**绝不能直接 `QFile::remove()`**。`moveToTrash` 在 Windows 上走 SHFileOperation，
在 Linux 上走 XDG trash，Mac 上走 Finder 回收站。
只有网络盘 / 特殊挂载点会失败，此时弹二次警告（文案里明确写「此操作不可恢复」），
用户点「否」就把这些列为失败项返回，**不做静默删除**。

#### ② 重命名的合法性校验

```cpp
static const QString illegal = "\\/:*?\"<>|";
for (const QChar c : name)
    if (illegal.contains(c)) return fail("名称不能包含这些字符");
if (name.endsWith('.') || name.endsWith(' ')) return fail("不能以空格或点号结尾");
```

Windows 上这几个字符会直接被文件系统拒绝，但**提前在中层拦截**能给出可读的中文提示，
而不是让 `QFile::rename` 返回一个含糊的 false。
`trail.` / `trail `（尾点、尾空格）也一并拦掉——Windows 会自动把它们截断，
导致「明明改名成功但名字不对」的诡异体验。

#### ③ 唯一命名：序号插在扩展名前面

```cpp
QString uniquePath(dir, "新建文件.txt");
// → 新建文件 2.txt   （而不是 "新建文件.txt2"）
```

实现上先拆 `stem` + `ext`，然后 `stem + " " + i + ext`。
`baseNameLength()` 配合它用于「重命名时只选中主干」：

| 文件名 | 选中长度 | 选中内容 |
|---|---|---|
| `main.cpp` | 4 | `main` |
| `a.b.c` | 3 | `a.b` |
| `.gitignore` | 10 | `.gitignore`（隐藏文件整体选中） |
| `makefile` | 8 | 整体 |

判断条件 `dot <= 0` 同时覆盖了「没有点」和「点在开头（隐藏文件）」两种情况。

#### ④ 属性对话框

用 `QDialog` + `QLabel(RichText table)` 手搭，而不是 `QFormLayout`：
表格形式能让「标签灰、值白」的对齐效果一次到位，也方便复制（`TextSelectableByMouse`）。

目录大小用递归 `dirSize()` 统计，带 24 层深度保护，避免软链接成环时死循环。

> ⚠️ 注意：`dirSize` 在 UI 线程同步执行。对超大目录（几十万文件）会卡住界面。
> 如果要处理那种量级，应该改成 `QtConcurrent::run` + 进度提示。

#### ⑤ 编译踩坑：`QChar + QChar` 是歧义的

```cpp
// ❌ 编译报 error: ambiguous overload for 'operator+'
s += c(ReadOwner) + c(WriteOwner);

// ✅ 用 QStringLiteral::arg 拼接
s += QStringLiteral("owner[%1%2]").arg(hasR ? "r" : "-", hasW ? "w" : "-");
```

`QChar` 支持和 `int` 相加（转成 Unicode 码点），又支持和 `QString` 相加，
两个 `QChar` 相加时编译器无法选择，只能显式转成字符串。

#### 重命名为什么用自定义委托

`QFileSystemModel::setReadOnly(false)` 能让模型自己改名，但那样：
1. 拦不住非法名字 / 目标已存在；
2. 拿不到「旧路径」去通知 MainWindow 同步标签页。

所以：模型保持 `setReadOnly(true)`，只用 `QTreeView::edit()` 让委托弹一个 `QLineEdit`，
回车后由我们自己调 `FileOps::rename()`，成功再发 `fileRenamed` 信号。

委托里**不用 `Q_OBJECT` + 自定义信号**，改用 `std::function` 回调：

```cpp
class RenameDelegate : public QStyledItemDelegate {
public:
    std::function<void(const QString &)> onCommit;   // 不需要 moc
    ...
    QObject::connect(ed, &QLineEdit::editingFinished, ed, [this, ed] {
        if (onCommit) onCommit(ed->text());
    });
};
```

**原因**：`.cpp` 文件里定义带 `Q_OBJECT` 的类，必须在文件末尾 `#include "fileexplorer.moc"`，
否则链接期报 vtable 未定义。用一个 `std::function` 就完全绕开了这个问题。

#### 信号 → 标签页同步（重要）

```cpp
signals:
    void fileRenamed(const QString &oldPath, const QString &newPath);
    void pathDeleted(const QString &path);
```

`MainWindow` 收到后调 `EditorTabs::notifyFileRenamed / notifyPathDeleted`。

**不接这两个信号会出两个隐蔽的 bug**：

| 场景 | 不接信号的后果 |
|---|---|
| 改名后按 Ctrl+S | `saveIndex()` 用的是标签里存的旧 `filePath`，会把内容**写回旧文件名**，等于复活了用户刚改走的文件（同时新文件里还是旧内容） |
| 删除后按 Ctrl+S | 标签还在，保存时 `QFile::open(WriteOnly)` 会**凭空把文件重新创建出来** |

删除目录时，`notifyPathDeleted` 还要连带关掉该目录下所有文件的标签：

```cpp
const bool hit = (p == targetAbs)
                 || (isDir && p.startsWith(targetAbs + QLatin1Char('/')));
```

删除同步的标签**不弹保存提示**——文件都没了，谈保存没有意义。

### 4.2 `mainwindow.cpp` 逐项

**(1) 构造函数**

```cpp
buildCentralArea();   // 新增：先搭左树 + 右标签
buildToolBar();
buildStatusBar();
resetEditorState();   // 新增：空态初始化
resize(1180, 760);    // 原 1080x720，加了侧栏所以变宽
```

原先的 `_editor = new CodeEditor(this); setCentralWidget(_editor);` 已删除。

**(2) `~MainWindow()` 清空，「关闭时问是否保存」迁到 `closeEvent()`**

产物：原实现（在析构函数里弹 `QMessageBox`）已不再安全 —— 析构阶段窗口树正在拆，
此时弹出模态对话框（尤其用户点「是」之后还要再弹 `QFileDialog` 另存为）行为不可预期。
因此把逻辑整体搬到 `closeEvent()`：

```cpp
void MainWindow::closeEvent(QCloseEvent *event)
{
    if (!_tabs) { QMainWindow::closeEvent(event); return; }

    // 从后往前：maybeClose 会 removeTab，倒序不会打乱未处理的下标
    for (int i = _tabs->count() - 1; i >= 0; --i) {
        if (!_tabs->editorAt(i)) continue;      // 跳过欢迎页
        if (!_tabs->maybeClose(i)) {
            event->ignore();                    // 用户取消：窗口不关
            return;
        }
    }
    QMainWindow::closeEvent(event);
}
```

`closeEvent` 的取消语义比析构里的 `return` 干净得多：
`event->ignore()` 能让 Qt 真正中止关闭流程，窗口保持原样。
**「关闭时询问」这一原有体验因此完整保留**，且对多个标签逐个检查。

> 代码审阅提示：`maybeClose` 对已保存的标签会 `removeTab` 并 `deleteLater`。
> 因为 `deleteLater` 是进事件队列、不是立即析构，所以在 `closeEvent` 里连续
> `removeTab` 是安全的。

**(3) `buildCentralArea()` —— 新函数**

```cpp
_splitter = new QSplitter(Qt::Horizontal, this);
_splitter->setHandleWidth(1);
_splitter->setChildrenCollapsible(false);   // 禁止拖到 0 宽消失
_splitter->addWidget(_explorer);
_splitter->addWidget(_tabs);
_splitter->setStretchFactor(0, 0);          // 拉伸时宽度给右边
_splitter->setStretchFactor(1, 1);
_splitter->setSizes({240, 940});
setCentralWidget(_splitter);
_explorer->setVisible(false);               // 未选文件夹时隐藏
```

`setStretchFactor(0,0)` + `setStretchFactor(1,1)` 是 QSplitter 里最常调的参数：
不加的话窗口放大时左右按比例一起变宽，侧栏会越来越肥。

**(4) `attachEditor()` —— 全篇最关键的「重新接线」**

```cpp
if (_connected && _connected != editor) {
    disconnect(_connected, &CodeEditor::cursorMoved,      this, &MainWindow::updateStatus);
    disconnect(_connected, &CodeEditor::foldStateChanged, this, &MainWindow::updateFoldActions);
}
if (editor && _connected != editor) {
    connect(editor, &CodeEditor::cursorMoved,      this, &MainWindow::updateStatus);
    connect(editor, &CodeEditor::foldStateChanged, this, &MainWindow::updateFoldActions);
}
_connected = editor;
```

原来的 `connect(_editor, ...)` 在构造里只做一次，现在编辑器会变，所以必须
**切一次标签就 disconnect 旧的 + connect 新的**。
用 `_connected` 记住当前接线对象，避免重复 `connect` 导致槽函数被调用多次。

**(5) 折叠按钮改转发**

```cpp
// 原：connect(_foldAllAct, &QAction::triggered, _editor, &CodeEditor::foldAll);
connect(_foldAllAct, &QAction::triggered, this, [this] {
    if (_editor) _editor->foldAll();
});
```

原来的写法把接收者绑死成构造时的 `_editor`，换标签后操作永远打在第一个编辑器上。
改成 lambda 转发到「当前」`_editor`。

**(6) 自动换行改「对所有编辑器生效」**

```cpp
connect(wrapAct, &QAction::toggled, this, [this](bool on) {
    for (int i = 0; i < _tabs->count(); ++i)
        if (CodeEditor *e = _tabs->editorAt(i))
            e->setWordWrapEnabled(on);
});
```

否则会出现「新开的标签不继承换行设置」的怪异体验。

**(7) `openFile()` 简化**

原函数里有 20 行「读文件 + 设标题 + 置 modified」的样板，现在整个下沉到 `EditorTabs::openFile()`：

```cpp
const QString path = QFileDialog::getOpenFileName(
    this, "打开文件",
    _explorer->rootPath().isEmpty() ? QString() : _explorer->rootPath(),   // 记住上次目录
    "所有文件 (*);;源代码 (*.cpp *.h *.hpp *.c *.py *.js *.qml *.txt)");
if (path.isEmpty()) return;
onFileActivated(path);
```

**(8) `saveFile()` 简化**

判断条件从 `_currentPath.isEmpty()` 换成 `_tabs->filePathOf(idx).isEmpty()`，
IO 交给 `EditorTabs::saveIndex()`。**`_currentPath` 成员已删除**——路径现在存在编辑器属性里，
多标签场景下不可能再用一个成员变量记路径。

**(9) 新增：`openFolder()`**

```cpp
const QString start = _explorer->rootPath().isEmpty()
    ? QStandardPaths::writableLocation(QStandardPaths::DocumentsLocation)
    : _explorer->rootPath();
const QString dir = QFileDialog::getExistingDirectory(
    this, "打开文件夹", start,
    QFileDialog::ShowDirsOnly | QFileDialog::DontResolveSymlinks);
```

`ShowDirsOnly` 隐藏文件只留目录；`DontResolveSymlinks` 防止选了快捷方式跳到别处。

**(10) 新增：`onFileActivated()`**

```cpp
if (!_tabs->openFile(path)) { statusBar()->showMessage("打开失败：..."); return; }
if (_explorer->rootPath().isEmpty() || !QDir(_explorer->rootPath()).exists()) {
    _explorer->openFolder(QFileInfo(path).absolutePath());
    _explorer->setVisible(true);
}
```

注意判断里加了 `!_rootPath.exists()`：命令行直接传一个**别的盘**的文件时，
侧栏会自动切到那个文件所在目录，而不是继续显示旧目录（否则用户会以为文件不在那儿）。

**(11) 工具栏新增两项**

```cpp
QAction *openDirAct = bar->addAction("打开文件夹");   // Ctrl+Shift+O
_explorerAct = bar->addAction("资源管理器");           // Ctrl+B，checkable
```

快捷键选 `Ctrl+Shift+O`（VS Code 同款），`Ctrl+B` 是通用「切换侧栏」。
